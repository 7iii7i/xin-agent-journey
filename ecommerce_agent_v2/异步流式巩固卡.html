异步 + 流式 巩固卡

电商客服 v2 · Tier 2 学完这张 = 异步与流式过关

await = 这一步要等，但我先放手去干别的
你原来的逻辑（取历史 → 跑 agent → 存答案）一行没变，只是「会等待的地方」前面机械地加了 await。

一、同步 vs 异步（后端怎么干活）

旧版（同步）
conn = sqlite3.connect(...)
conn.execute(...)
conn.commit()
每一步都卡住当前线程，别人只能干等。
新版（异步 Tier2）
async with aiosqlite.connect(...) as db:
    await db.execute(...)
    await db.commit()
等待时放手去服务别人，并发更高。
关键现象：async 会传染整条链 —— 一个函数变 async，调用它的函数都要 async + 在它前面加 await（见 agent.py / main.py 里一串 await）。

二、一次性 vs 流式（答案怎么到你眼前）

旧版（一次性）
return 回复.content
# 接口层：
return {"answer": 答案}
转圈等 2-5 秒，啪一下整段出现。
新版（流式 Tier2）
yield d.content
# 接口层：
StreamingResponse(事件流())
# 流里每字推：
yield f"data: {...}\n\n"
立刻开始，字一个个蹦（打字机）。
设计决策：工具轮用非流式（干净拿「调哪个工具+参数」），最终轮才用流式（打字机）。因为流式里的 tool_calls 是碎片、要手拼，容易出 bug —— 这是踩坑后的最优解。

三、学到什么程度

死记 以下三处要能闭眼写：

  • async def + yield 生成器：async def 跑_agent(历史): ... yield d.content
  • SSE 那行：yield f"data: {json.dumps(token, ensure_ascii=False)}\n\n"
  • aiosqlite 套路：async with aiosqlite.connect(...) as db: + await db.execute/commit

懂框架 以下能讲清即可，不用背：

  • 为什么异步：不卡线程、并发高
  • 一次性 vs 流式 的体验差异
  • 「工具轮非流式 / 最终轮流式」的设计原因
  • async 会传染整条链
  • CORS / 配置分层（pydantic-settings）是干嘛的
