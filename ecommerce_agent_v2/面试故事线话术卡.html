面试故事线话术卡

v1.1 → 工厂库存 → v2 → 闲鱼RPA，一套 Agent 架构的演进（照着讲）

脉络：验证骨架 → 跨领域复用 → 生产级深化 → 真实业务闭环
本卡把 4 个项目拧成「我做了什么、踩了什么坑、怎么解决」一条线。面试时按"递进"讲，比逐个罗列项目强。规则：🔴 该背的要点 / 🟢 理解即可。

一、开场一句话（自我介绍）

我叫耿忻，28 岁，大专会计专业转行，半年自学 Python + LLM 应用，目标 Agent 开发工程师。
我能独立搭出「分层架构 + 工具调用 + 会话记忆 + 异步流式 + RAG 检索」的 Agent 服务，并用 Docker 容器化交付。
最大差异化：我的项目全来自真实业务（电商客服 / 工厂库存 / 无货源电商），不是玩具 demo——这是别人简历没有的落地证据。
⚠️ 主动提"大专学历在初筛有劣势，所以我用真实项目 + 能讲清原理来补"。诚实比遮掩加分。

二、项目递进（按这个顺序讲）

① 电商客服 v1.1（端口 8001）
单文件 main.py · 同步 · 关键词查 · 验证核心骨架
做了什么：用 DeepSeek 做一个一句话客服，能「搜商品 / 查价格 / 查库存」。
技术点：SQLite 四步封装（建表→播种→查→关） + 工具清单（3 个 function）+ Agent 三件套（while / if tool_calls / 历史.append）+ FastAPI 暴露接口。
价值：第一次把"LLM 自己决定调哪个工具"跑通，证明架构可行。
局限（面试主动说）：同步、单文件、无记忆、工具用 if-elif 硬编码、关键词查（= 朴素 RAG 前身）。
② 工厂库存查询（端口 8002）
单文件 + 已 Docker 化 · 企业场景 · 证明架构可复用
做了什么：同一套 Agent 骨架，换成「工厂库存」领域——大白话问"螺丝还有多少""给钢板入库 100 公斤"，AI 自动查 / 改库存库。
技术点：库存库 class（成品 / 原料 / 备件，含写操作 入库 / 出库）+ 4 工具 + 同款 Agent 三件套 + Docker 容器化（Dockerfile / compose / 部署说明，能上云、能打包 exe）。
价值：证明"同一套 Agent 架构能快速适配不同业务"——这是架构复用的硬证据，不是重写。
🟢 懂框架：写操作（入库 / 出库）要 UPDATE + commit，比 v1.1 只读多一步"落库"，并要防"没找到该物品"的边界。
③ 电商客服 v2（端口 8003）⭐ 简历主项目
分层 10 文件 · 异步 + 流式 + RAG · 生产级
做了什么：把 v1.1 升级成生产级——分层、异步、打字机流式、会话记忆、RAG 语义检索，全套工业界交付。
技术点（逐条讲）：
  • 分层架构：config / db / tools / agent / main 各司其职，职责清晰可维护
  • 工具注册表（类封装）：加工具只一行 `注册表.注册(...)` —— 开闭原则，加能力不动旧代码
  • 异步全链路：aiosqlite + AsyncOpenAI + async 生成器，高并发不卡
  • SSE 流式：`yield f"data:..."` + StreamingResponse，前端打字机效果
  • 服务端会话记忆：sessions.db 存历史，多轮对话 + 多用户隔离
  • RAG 向量知识库：kb_search 工具，文档切片→embedding→向量库，口语化政策问答（朴素关键词查→语义检索）
  • Docker + pytest + README：容器化部署 + 离线测试 + 交付说明
价值：从"能跑"到"能交付"——面试官看到 Docker + 测试 + 分层，就知道是工业界标准做法。
④ 闲鱼上架 RPA（无货源电商）
Playwright 浏览器自动化 · 真实现金流业务
做了什么：用 Playwright 自动操作浏览器，把 1688 选品结果自动上架到闲鱼——真实业务闭环，不是 demo。
技术点：浏览器自动化（探针 / 登录态保持 / 表单填写 / 发布）+ 选品数据流转。
价值：这是差异化筹码——别人简历是技术玩具，你有"Agent / 自动化真在产生业务价值"的证据。
🟢 懂框架：RPA 解决"没开放 API 的网站只能模拟人点"的问题；和前面 Agent 是两套能力，合起来 = 选品(爬虫)+客服(Agent)+上架(RPA) 全链路。

三、技术亮点（按考点准备）

  • Agent 架构三板斧 🔴：分层解耦 + 工具注册表（开闭原则，加工具不动旧代码）+ 服务端会话记忆（多轮 / 多用户隔离）。这是你最硬的核心能力。
  • 异步工程 🟢：asyncio 全链路（async 像传染病，从 db 一路传染到入口）+ aiosqlite 不阻塞 + SSE 流式让响应"边生成边显示"。
  • RAG 🟢：朴素（关键词查）vs 真（embedding 向量 + 余弦相似 + rerank 两阶段粗排精排）；RAG 不替代 SQLite，前者管语义文本、后者管精确数字，模型按"数据类型"自己选工具。
  • 部署 🟢：Docker 把"代码 + 依赖"打包成可复现标准件；配置分层（pydantic-settings）；密钥用 env_file 运行时注入、不进镜像。
  • 测试 🟢：pytest 离线验证 Agent 分发 / 会话隔离 / 工具调用逻辑——和 Docker"验环境"是两回事。

四、踩坑与解法（面试最爱问）

坑 1：系统 Python 缺依赖，服务起不来
解法：用受管 venv 隔离装包（fastapi / aiosqlite / pydantic-settings），不污染系统环境。懂框架 体会：环境隔离是基本功。
坑 2：异步"传染"导致整条链报错
db 改成 aiosqlite 后内部要 await，于是 注册表.调用()、跑_agent()、main 的 ask() 全得 async。死记：一个函数标 async，调用它的整条链都得 async。
坑 3：pytest 漏初始化商品库，测试失败
只初始了会话库，没初始商品库 → 检索无数据。补 `商品库实例.初始化()` 后 2 passed。懂框架：测试要还原真实运行的前置条件。
坑 4：DeepSeek 没有 embedding 接口，RAG 卡住
原想 embedding 走同一厂商 API，但 DeepSeek 只给对话接口。改本地中文模型 BAAI/bge-small-zh，封装成一处函数，想换 API 只改这处。懂框架：选模型看"有没有这个能力"，不是只看厂商。
坑 5：Docker 引擎没启动，沙箱构建失败
文件正确，只是沙箱 Docker Engine 没跑。本机 `docker compose up --build -d` 验证即可。懂框架：先确认引擎在运行再 build。
坑 6：RAG 检索排序"假模型"翻车
教学版 embedder 靠手列同义词，漏了"修"字就把"耳机坏了给修吗"错匹配到耳机段。真实 bge 模型自动从海量中文学语义，不用手列、更稳。懂框架：神经网络 embedding 优于规则同义词。

五、面试官可能反问 + 你的回答要点

Q：RAG 为什么不直接查数据库？
A：SQLite 管精确数字（价格 / 库存），RAG 管语义文本（政策 / 说明）。两者并存，模型按"问题要哪类数据"自己选工具——不是替代关系，是互补。
Q：多轮对话怎么保证不串用户？
A：服务端用 session_id 区分，历史存 sessions.db；每个请求带自己的 session_id 取对应历史，天然隔离。前端 session_id 存 localStorage。
Q：rerank 为什么分两步，不直接用最准的？
A：cross-encoder 精排要把"问题 + 文档"拼一起现算，不能预存，全量实时跑太慢。所以先用 bi-encoder 预存向量快捞 top-20（粗排保证不漏），再 cross-encoder 只给这 20 段精排取 top-3（精排保证前几条真相关）——速度 vs 精度的权衡。
Q：怎么评估你的 Agent 好不好？
A：代码层用 pytest 离线验逻辑；RAG 层用评估集跑 recall / 命中率 / 忠实度。每次改切片策略或换模型都跑一遍，用数据驱动调参，不是凭感觉。
Q：你学历是专科，怎么补？
A：我用真实项目 + 能讲清原理来补。我的 Agent 从架构到部署全链路自己搭过、跑通过、踩过的坑能说清，比只看教程的人落地能力强。贵司要的是能干活的人，我证明过我能。

六、你该「死记」vs「懂框架」的边界

死记（闭眼能写骨架）
  • Agent 三件套：while / if tool_calls / 历史.append（含 choices[0]）
  • 工具注册表：注册表.注册(schema, 函数) + 注册表.调用(名, 参数)
  • SQLite 四步：connect → execute → commit/close
  • SSE 两行：yield f"data: {...}\n\n" + return StreamingResponse(..., media_type="text/event-stream")
  • async 生成器：async def 跑_agent(历史): yield d.content
懂框架（理解 + 会改即可）
  • 分层依赖方向、会话隔离原理、RAG 原理（embedding / 向量库 / rerank 两阶段）
  • Docker（镜像 / 卷 / 密钥注入 / 分层缓存）、pytest 离线测试思路
  • 多 Agent 编排、记忆系统、评估观测、K8s/CI-CD（阶段 2–3，待学）
定位：代码 AI 写、自己懂原理 + 会看 + 能审。不要求从零手写每个框架，会看、能评审、能指挥即可。
