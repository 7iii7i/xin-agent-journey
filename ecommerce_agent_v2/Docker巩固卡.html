Docker 巩固卡

电商客服 v2 · Tier 3 学完这张 = 容器化部署过关

Docker = 把「代码 + 运行环境」封成一个谁拿到都一模一样跑的标准件
终极意义：消灭「在我机器能跑、到你那跑不了」。公网部署只是它最常用的一个落点，不是全部。

一、这一步包含哪 3 个文件

  • Dockerfile：镜像构建配方（怎么把项目装进容器）
  • docker-compose.yml：一键起服务 + 端口 / 卷 / 密钥配置
  • .dockerignore：排除不该打进镜像的（密钥 / 缓存 / 本地库）
三者全是 懂框架：理解每句干嘛、会改端口 / 卷名即可，不用背原文。

二、Dockerfile 的几个关键点（为什么这么写）

易踩坑
CMD ["uvicorn","main:app",
    "--host","0.0.0.0",
    "--port","8003"]
CLI 方式不读 config.端口，必须显式写 --port 8003，否则容器内起在 8000、外面映射 8003 对不上。
正确做法
COPY requirements.txt .
RUN pip install -r requirements.txt
COPY . .          # 源码后复制
ENV PYTHONIOENCODING=utf-8
① 依赖先装、源码后复制 = 分层缓存，改代码不重装包；② 中文编码兜底防 ascii 报错。
死记 Dockerfile 套路顺序：FROM → ENV → WORKDIR → COPY 依赖 → RUN pip → COPY 源码 → EXPOSE → CMD。改项目时照这个顺序填空。

三、compose 一条命令起服务

docker compose up --build -d   # 构建 + 后台启动
docker compose logs -f         # 看日志
docker compose down            # 停止
  • ports: "8003:8003"：宿主机 : 容器内，必须一致
  • env_file: .env：密钥运行时注入，不打进镜像
  • volumes: agent_data:/app/data：会话 / 商品库持久化，容器删了数据还在
  • restart: unless-stopped：意外退出自动重启
死记 那条启动命令 docker compose up --build -d 你会真敲，记熟。

四、Docker 到底图啥（vs 没有 Docker）

没有 Docker
你的机器：Py3.13+依赖 ✓
同事/云：Py3.11、缺依赖
→ 跑不起来
每换一台机器都要重配环境。
有 Docker
代码+依赖+系统库
→ 封成 1 个 image
任何装 Docker 的机器 ✓
一次构建，到处运行。
三层真正价值（懂框架）： ①环境一致性（自带依赖，到哪都一样）、 ②可移植（同事本 / 内网 / CI / 云 / K8s 都是一个 image）、 ③隔离（不污染本机、不跟别的版本打架）。

五、澄清：「检验」≠ 找 bug

pytest（早就有）
找逻辑 bug
分发对不对 / 会话隔离 /
工具调用……
测的是「代码对不对」。
Docker 的「检验」
验环境可复现
依赖齐不齐 / 干净机器
能不能跑起来
测的是「环境掉不掉链子」。
两者不冲突，Docker 替代不了 pytest。前面说的「Docker 用来检验」指的就是验「环境可复现」，不是找代码 bug——别混。

六、只在我本机 / 局域网跑？要不要放公网？

  • 懂框架 默认 docker compose up 就在你本机起，localhost:8003 能访问；同局域网用你内网 IP 也能访问（手机 / 同事电脑）。
  • 懂框架 「只能局域网」不是 Docker 限制，是「你没放公网」。想公网可访问有两条路：① 把镜像推到云服务器（ECS / 容器服务）跑 —— 因为 image 可移植，直接搬过去就行；② 家用宽带做端口映射（不推荐，不稳且有风险）。
  • 懂框架 简历项目不必真放公网：本地 docker compose up --build -d 跑通 + 截图，已足够证明你会 Docker 部署。真要远程 demo 给面试官看才需要上云或内网穿透。

七、学到什么程度

死记 以下三处要能默写 / 照敲：

  • Dockerfile 套路顺序：FROM → ENV → WORKDIR → COPY 依赖 → RUN pip → COPY 源码 → EXPOSE → CMD
  • 那条启动命令：docker compose up --build -d
  • CMD 必须显式 --port 8003：CLI 不读 config.端口，漏写端口对不上

懂框架 以下能讲清即可，不用背：

  • 分层缓存为什么（依赖先装、源码后复制）
  • 中文编码兜底 ENV 防 ascii 报错
  • env_file 注入密钥（密钥不打进镜像）
  • volume 持久化（容器删了数据还在）
  • 镜像（模板，只读可复用）vs 容器（跑起来的实例，有状态可重启）
  • 双身份：检验环境可复现 + 工业界标准交付
  • 公网 vs 局域网：默认本机 / 局域网，公网靠上云（镜像可移植）
