## 2. for 循环的概念模型（缩进=重放 / 每轮一个元素）

- **发现日期**：2026-09-07
- **来源**：题 1 解释 `total` 时
- **原话**："循环这个总的概念我还是不懂" / "在for下面的代码都是循环整个字典吗"
- **正确做法**：
  1. `for` = 复读机：缩进代码对集合每个元素**重放一遍**（列表几个元素重放几次）
  2. 缩进内 = 每遍重放；缩进外 = 整程序只跑一次
  3. 字典默认遍历**键**（要值用 `.values()`，要键值对用 `.items()`）
  4. 每轮 `x` 只面对【一个】元素，不是整个集合
- **第一轮掌握情况**：✅ 已掌握（正常数据 + 3 个边界场景都跑出"小明/未知"，无崩溃）
- **下次复测**：week02 day2 末尾顺手带一题（改 raw 字段顺序或缺中间层）

## 3. try/except/else 的正确结构

- **发现日期**：2026-09-07
- **来源**：题 2
- **原话**：第一版 `print` 已写完又包了个多余 `try: resp=json.loads(raw)`、`except` 兜底是空 print
- **正确做法**：
  1. `try` 包**第一个会崩的操作**（这里 `json.loads`）
  2. `except` 写兜底动作（这里 `print("未知")`）
  3. `else` 写"没崩才执行"（这里 `.get` 链 + `if nickname`）
  4. 不要重复 `try` 同一个 `loads`
  5. 进阶：except 范围尽量精确（`json.JSONDecodeError` 而非 `Exception`）
- **第一轮掌握情况**：✅ 已掌握（结构、缩进、`else` 收尾都对）
- **下次复测**：涉及文件读写 / 网络请求时，try 块要包含整个"可能失败"的动作链
- **小备注**：`except Exception` 还能用，但工程上应收紧到具体异常类型

## 4. class 概念模型（模板 vs 实例 / self 是什么）

- **发现日期**：2026-09-07
- **来源**：题 3（class 记账本 AccountBook）
- **原话**："第三题完全听不懂 从头开始讲"
- **正确做法**：
  1. `class X:` 定义的是【模板】，不是实物；必须 `x = X()` 才开出一个真正可用的对象
  2. `__init__(self)` 是"开新对象时自动跑"的初始化（本例里给账页 `self.records = []`）
  3. `self` = "当前这个对象自己"；**定义时**用到的"对象自己的东西"都加 `self.` 前缀
  4. `def 方法(self, ...)` = 这个对象能做的【动作】（记账/算总/看账）
  5. **调用时永远不写 self**：`book.add(12,"早饭")`、`book.total()`，self 由 Python 自动塞
- **第一轮掌握情况**：✅ 已掌握（用户自己从空白写出完整 AccountBook 并跑通，输出"支出…-…"×3 + 总额 67；self/累加器/show-for 全对，仅 show 格式少"元"和空格，不影响通过）
- **下次复测**：用户把题 3 代码 + 输出发回后批；或 week02 day2 出"再写一个小类"专项测
- **第二轮验证（2026-09-07 晚 22:22）**：`level_test/class_practice_cart_0907.py` 购物车换场景练习通过 ✓
  - 用户独立把 `AccountBook → Cart` 迁移：self.items 列表、`add(name, price, qty)`、total 用 sum 写 `r["price"]*r["qty"]`、show 用 for+f-string
  - 4 个方法全对，**能换场景不抄模板 = 真正掌握**
  - 小细节：`sum([...])` 方括号版（生成器用圆括号更规范）；show 用了"先取变量再格式化"风格（可读但不简）

## 5. 字典字段: 字符串 vs 数字别搞混(sum 不能加字符串)
